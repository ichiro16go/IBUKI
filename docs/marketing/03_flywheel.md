# Ibuki フライホイール（成長ループ）

## コールドスタート問題と解決戦略

### 問題: すれ違いはネットワーク効果に依存する

```
従来の考え方（問題あり）:
ユーザー数増加 → すれ違い頻度UP → 価値UP → ユーザー数増加

問題点:
- ユーザーが少ない初期段階では「すれ違いが起きない」
- 価値が出ない → 離脱 → さらにユーザー減少
- 「鶏と卵」問題
```

### 解決: シングルプレイヤーモード → マルチプレイヤーモードへの移行

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  Phase 1: シングルプレイヤーモード                          │
│  「一人でも価値がある趣味ログアプリ」                       │
│           ↓                                                 │
│  Phase 2: マルチプレイヤーモードの解放                      │
│  「すれ違いで他者の趣味と出会う」                           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

## Phase 1: シングルプレイヤーモード

### コンセプト: 「自分だけの趣味図鑑を作る」

一人でも完結する価値を提供し、ユーザー基盤を構築する。

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  [自分の趣味を登録]                                         │
│        │                                                    │
│        ▼                                                    │
│  [趣味ログ（suki_action）を記録]                            │
│        │                                                    │
│        ▼                                                    │
│  [ステータスが成長: 興味あり → 好き → 大好き → 熱狂]       │
│        │                                                    │
│        ▼                                                    │
│  [図鑑が充実 = 自分の「好き」の履歴書]                      │
│        │                                                    │
│        ▼                                                    │
│  [振り返り・自己理解が深まる]                               │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### シングルプレイヤーで提供する価値

| 機能 | 価値 | 競合との違い |
|------|------|-------------|
| **趣味ログ記録** | 自分の活動を可視化できる | NotionやEvernoteより趣味特化 |
| **ステータス成長** | 趣味への投資量が見える化 | ゲーミフィケーションで継続動機 |
| **図鑑コレクション** | 「自分の好き」を整理できる | SNSのような消費ではなく蓄積 |
| **始め方ガイド** | 新しい趣味を始める参考に | 趣味特化のナレッジベース |

### シングルプレイヤー時のユーザーストーリー

```
[田中のケース - すれ違い機能なしでも価値を感じる]

Day 1: アプリDL
→ 「今の趣味を登録してみよう」
→ ゲーム、アニメ、カフェ巡りを登録

Day 7: 趣味ログを初投稿
→ 「新しいカフェに行った」を写真付きで記録
→ カフェ巡りのステータスが「好き」に上昇

Day 30: 図鑑を眺める
→ 「意外と自分、カフェ巡り好きなんだな」と気づく
→ 自分の「好き」が可視化されて満足感

Day 60: 新しい趣味に興味
→ 「何か新しいこと始めたいな」
→ アプリ内の「おすすめ趣味」から探す
→ （この頃にはユーザー数が増え、すれ違い機能が活きてくる）
```

## Phase 2: マルチプレイヤーモードへの移行

### 移行のトリガー

```
┌─────────────────────────────────────────────────────────────┐
│                                                             │
│  条件1: ユーザー密度がクリティカルマスに到達                │
│  → 特定エリアで「すれ違い」が1日1回以上発生する状態        │
│                                                             │
│  条件2: ユーザーの趣味ログが蓄積                            │
│  → 「流れてくる趣味」の質が担保される                      │
│                                                             │
│  条件3: ユーザーがアプリに愛着を持っている                  │
│  → シングルプレイヤーで価値を感じ、継続している            │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 移行戦略: 段階的なすれ違い機能の解放

| フェーズ | すれ違い判定範囲 | 理由 |
|----------|------------------|------|
| 初期（MAU 1,000未満） | 500m〜1km | 密度が低いため広めに設定 |
| 成長期（MAU 1,000-10,000） | 100m〜500m | 徐々に精度を上げる |
| 成熟期（MAU 10,000+） | 10m〜50m | 本来の「すれ違い」体験 |

※ アルゴリズムによる「レア出現率UP」は偶然性のコンセプトに反するため採用しない。代わりに物理的な判定範囲で調整する。

## 成長ステージ別戦略

### Stage 0: MVP検証期（MAU 0 → 100）

```
[重点施策]
・シングルプレイヤー機能の完成度を上げる
・少数のテストユーザーで「一人でも使いたいか」を検証
・すれ違い機能はOFF or 非常に緩い設定（1km以内）

[KPI]
・7日継続率: 30%以上
・1人あたり趣味ログ投稿数: 週2件以上

[この段階の問い]
「すれ違い機能がなくても、趣味ログアプリとして使いたいか？」
→ Yesなら次へ、Noなら機能を改善
```

### Stage 1: シード期（MAU 100 → 1,000）

```
[重点施策]
・趣味系インフルエンサーとの連携
  → 「自分の趣味を可視化するアプリ」として紹介
・趣味コミュニティでのプロモーション
  → Reddit的なコミュニティ、Discord等
・すれ違い判定範囲: 500m（広め）

[KPI]
・MAU: 1,000
・1日1回以上のすれ違い発生率: 20%のユーザー

[この段階では大学ターゲティングを避ける理由]
・大学の需要は「知り合いが何を好きか」という内輪ノリ
・匿名性の高いIbukiでは、この需要を満たせない
・代わりに「趣味への熱量が高い人」が集まる場所を狙う
```

### Stage 2: 密度達成期（MAU 1,000 → 10,000）

```
[重点施策]
・すれ違い体験の質向上
  → 判定範囲を徐々に狭める（500m → 100m）
・「すれ違いで発見」の価値を訴求
  → シングルプレイヤーで定着したユーザーに新体験を提供
・エリア別の密度モニタリング

[KPI]
・1日1回以上のすれ違い発生率: 50%のユーザー
・すれ違いからの図鑑追加率: 30%

[このタイミングでマルチプレイヤー価値が本格化]
```

### Stage 3: 自律成長期（MAU 10,000 → 100,000）

```
[重点施策]
・すれ違い判定を本来の距離に（10m〜50m）
・口コミ・バイラルループの強化
・収益化テスト

[KPI]
・バイラル係数: 0.3以上
・月間収益: 100万円

[フライホイールが自律的に回り始める]
```

## 大学ターゲティングの代替案

### 問題点の整理

| 大学ターゲティングの前提 | Ibukiとの矛盾 |
|--------------------------|---------------|
| 「知り合いが何を好きか知りたい」 | 匿名なので誰のsukiかわからない |
| 「友達と同じ趣味を共有したい」 | 人ではなく趣味だけが流れる |
| 「内輪ノリで盛り上がりたい」 | 匿名性重視で内輪感が出ない |

### 代替ターゲット

| ターゲット | 理由 | アプローチ |
|------------|------|-----------|
| **趣味系インフルエンサーのフォロワー** | 趣味への熱量が高い、新しい趣味に興味がある | インフルエンサーとのコラボ |
| **趣味イベント参加者** | 同じ場所に集まる、趣味への関心が高い | コミケ・音楽フェス・展示会でのプロモ |
| **クリエイター・ものづくり系** | 自分の活動を記録・発信する習慣がある | Pixiv・note・Zennユーザー |
| **複業・副業に興味がある層** | 新しいスキル・趣味を探している | 転職・スキルアップ系メディア |

## フライホイールの弱点と対策（再整理）

| 弱点 | リスク | 対策 |
|------|--------|------|
| **シングルプレイヤーで飽きる** | すれ違い機能が活きる前に離脱 | ステータス成長・バッジ・週間レポートで継続動機 |
| **すれ違い判定が緩いと価値が薄い** | 「500m先の人とすれ違った」では感動がない | UI/UXで「偶然の出会い」感を演出 |
| **匿名なので内輪ノリが生まれない** | 大学等でのバイラルが起きにくい | 「内輪ノリ」ではなく「偶然の発見」を価値として訴求 |
| **趣味ログ系アプリとの競合** | Notion等で代替される | 趣味特化のUI/UX、ゲーミフィケーションで差別化 |

## 密度達成までの「つなぎ」施策

### アイデア: AIによる「仮想すれ違い」

密度が低い初期段階で、完全にすれ違いが起きないと体験が空っぽになる。その対策として：

| 施策 | 詳細 | 懸念点 |
|------|------|--------|
| **シードコンテンツの投入** | 運営側で多様なsukiカードを事前登録し、初期ユーザーの図鑑に入れる | 「偶然性」の演出が必要 |
| **位置ベースのレコメンド** | 「この場所でよく見つかるsuki」として提供 | アルゴリズム感を出しすぎない |
| **イベント連動** | イベント参加者限定で特定sukiを配布 | 限定感・偶然感を演出 |

※ いずれも「アルゴリズム推薦」ではなく「偶然の発見」という世界観を損なわない形で実装

### 検証すべき仮説

1. **「趣味ログアプリ」として一人でも使いたいと思うか？**
   - MVP検証で確認
   - NoならIbukiの根本設計を見直す必要あり

2. **すれ違い判定範囲を広げても「偶然の出会い」感を演出できるか？**
   - UI/UXのテストで確認
   - 「500m先の人のsuki」でも価値を感じるか？

3. **シングルプレイヤー → マルチプレイヤーへの移行でユーザーは喜ぶか？**
   - 段階的リリースで確認
   - すれ違い機能のオン/オフでリテンションに差が出るか？
